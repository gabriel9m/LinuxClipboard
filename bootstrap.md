# Bootstrap de novo projeto

Use este roteiro ao iniciar um projeto novo.

## 1. Copiar a base

- Copie `codex.md` para o novo projeto.
- Copie `governanca-ambiente.md` para registrar isolamento, versionamento e acesso ao GitHub.
- Copie `project-brief.template.md` e renomeie para `project-brief.md`.
- Copie `fluxo-akita.md` se quiser manter o mesmo rito de trabalho no novo projeto.
- Copie `prompt-abertura.md` se quiser iniciar a conversa com a IA já no formato certo.

## 2. Preencher o briefing

- Descreva em linguagem simples o que você quer construir.
- Não tente decidir stack sozinho se isso depender de conhecimento técnico.
- Informe restrições, preferências e o resultado esperado.

## 3. Pedir análise técnica

Peça para a IA retornar opções por categoria, por exemplo:

- linguagem de programação;
- banco de dados;
- front-end;
- back-end;
- autenticação;
- testes;
- deploy;
- infraestrutura.

Quando falar do atalho principal no Linux, use `Super+V` como nomenclatura padrão e trate `Win+V` apenas como a referência equivalente no Windows.

## 4. Decidir com apoio da IA

- Leia as opções com prós e contras detalhados.
- Exija alternativas para toda decisão técnica relevante.
- Faça perguntas adicionais se algo não estiver claro.
- Escolha a direção técnica antes de começar a implementação.

## 5. Iniciar o ciclo do método

1. Briefing inicial
2. Governança e ambiente
3. Domínio e especificação
4. Testes e contratos
5. Implementação core
6. Poda e refatoração
7. Segurança e hardening
8. Interface e deploy

## Regra principal

O briefing vem do usuário.
A análise técnica vem da IA.
A decisão final vem do usuário com base nessa análise.
